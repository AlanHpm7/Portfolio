Networked elevator control system

Engineering Projects VI / Spring 2025 / with Kyle Dick
View source on GitHub ↗

A distributed elevator control system that emulates real industrial automation practice. A Raspberry Pi reads floor requests from a MySQL-backed web GUI and sends commands over CAN bus to an Arduino-driven motor controller. Every event is logged twice, once at the application layer and once on the CAN network itself, for full traceability.

The feature I'm most proud of is Maintenance Mode. Dedicated STM32 boards give technicians physical, network-independent control of the elevator for on-site servicing. If the GUI or network goes down, the elevator can still be operated safely from the hardware itself.

  • TimingGetting the GUI, PHP backend, and C++ controller to agree on state was harder than it sounds. Small mismatches caused skipped or repeated floor commands until we tightened up the polling and acknowledgment logic.
  • AudioReal-time two-way emergency voice over ALSA and TCP sockets had jitter and first-connect bugs that took a few evenings of packet-poking to nail down.
  • Mode separationKeeping Standard, Sabbath, and Maintenance modes cleanly separated while still logging every transition meant rewriting the state machine twice before I was happy with it.
